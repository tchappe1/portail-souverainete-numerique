> [!abstract] Objectif
> Cette fiche définit les règles à donner à une IA pour produire une **famille cohérente de schémas**, à partir du schéma de référence **« Le Cerveau collectif »**.
>
> L'objectif est que les prochains schémas aient immédiatement le même ADN visuel, même lorsqu'ils représentent d'autres concepts de la souveraineté numérique.

## 1. Schéma de référence

Le schéma de référence est celui de **« Le Cerveau collectif »**.

Il doit servir de référence prioritaire pour :

- la composition ;
- les proportions ;
- la hiérarchie visuelle ;
- la typographie ;
- les couleurs ;
- le style des icônes ;
- les connecteurs ;
- les cartes ;
- les effets lumineux ;
- le niveau de détail ;
- le degré d'épuration.

**Principe : ne pas réinventer le style à chaque nouveau schéma.**

Le contenu et la structure peuvent changer, mais le langage graphique doit rester reconnaissable.

---

# 2. ADN visuel

## 2.1 Style général

Le style recherché est :

- **moderne** ;
- **professionnel** ;
- **technologique mais humain** ;
- **éditorial / stratégique** ;
- **léger et lumineux** ;
- **très épuré** ;
- adapté à une **présentation PowerPoint / Google Slides** ;
- suffisamment élégant pour être également utilisé sur le web.

Éviter :

- le style cartoon ;
- les illustrations 3D réalistes ;
- les interfaces trop « SaaS » ;
- le dark mode ;
- les couleurs saturées en abondance ;
- les ombres fortes ;
- les gros contours ;
- les effets « futuristes » excessifs.

---

# 3. Fond

### Règle

Utiliser un **fond blanc ou blanc cassé très légèrement bleuté**.

Le fond doit rester presque blanc.

Il peut comporter de très légers halos ou dégradés bleu pâle, mais ils doivent rester secondaires.

### À éviter

- grands aplats de couleur ;
- fonds sombres ;
- textures ;
- motifs décoratifs visibles ;
- grilles trop présentes.

---

# 4. Palette

La palette doit rester **très limitée**.

## Couleurs principales

| Usage | Couleur indicative |
|---|---|
| Texte principal | `#102957` |
| Bleu principal | `#1769E8` |
| Bleu clair | `#66A9FF` |
| Bleu très pâle | `#EEF5FF` |
| Turquoise / apprentissage | `#16C8AA` |
| Violet secondaire | `#7357E8` |
| Gris bleu | `#7890B8` |
| Bordures | `#DDE7F4` |
| Fond carte | `#FFFFFF` |

### Règle importante

Le **bleu est la couleur dominante**.

Le turquoise sert principalement :

- aux boucles ;
- aux flux d'apprentissage ;
- aux signaux positifs ;
- à certains accents.

Le violet sert uniquement comme **accent secondaire**.

Les couleurs propres aux logos de services (GPT, Claude, etc.) peuvent être conservées lorsqu'elles sont nécessaires à l'identification.

> [!important]
> **Ne pas multiplier les couleurs pour différencier chaque élément.**
> La cohérence prime sur le codage couleur.

---

# 5. Typographie

Utiliser une police sans-serif moderne.

Préférence :

1. **Inter**
2. Arial / Helvetica comme fallback.

## Hiérarchie

### Titre principal

- très grand ;
- gras ;
- bleu nuit ;
- un mot clé peut être en bleu principal.

Exemple :

**Le Cerveau** `collectif`

### Titres de sections

- gras ;
- bleu nuit ;
- taille importante mais nettement inférieure au titre principal.

### Sous-titres

- bleu/gris ;
- poids normal ;
- courts.

### Labels

- petits ;
- lisibles ;
- peu de mots.

### Micro-texte

Pour les légendes et indications techniques :

- petites capitales ou petites tailles ;
- espacement légèrement augmenté ;
- bleu/gris.

---

# 6. Composition

Le schéma doit privilégier une **lecture de gauche à droite**.

Structure de référence :

```text
COLLECTIF
    ↓
CONTRIBUTIONS / SOURCES
    ↓
MÉMOIRE / CONNAISSANCE
    ↓
ORCHESTRATION
    ↓
IA / CAPACITÉS
    ↓
ANALYSE / ACTION
    ↓
APPRENTISSAGE
    ↺
```

Cette logique peut être adaptée selon le sujet, mais la lecture doit rester immédiatement compréhensible.

## Règle des niveaux

Limiter le schéma à **4 à 6 grandes zones conceptuelles**.

Chaque zone doit avoir :

- un titre ;
- éventuellement un sous-titre ;
- quelques éléments visuels ;
- une fonction clairement identifiable.

Éviter les longues listes.

---

# 7. Cartes et blocs

Les cartes doivent être :

- blanches ;
- légèrement arrondies ;
- bordure très fine ;
- ombre extrêmement légère ;
- beaucoup d'espace blanc.

### Rayon indicatif

`12–28 px`

selon la taille de l'objet.

### Ombres

Utiliser uniquement une ombre douce :

- faible opacité ;
- grand flou ;
- aucun effet « boîte flottante » prononcé.

---

# 8. Icônes

Les icônes doivent être cohérentes entre elles.

Style recommandé :

- **outline / flat vector** ;
- formes simples ;
- angles légèrement arrondis ;
- épaisseur de trait fine ;
- très peu de détails ;
- taille homogène.

### Personnes

Pour les collaborateurs :

- avatars circulaires ;
- diversité visible ;
- style illustratif simple ;
- expressions neutres / positives ;
- pas de photoréalisme.

Les avatars doivent représenter **un collectif**, pas des individus identifiables.

### Documents

Utiliser des icônes simples :

- PDF ;
- Word ;
- Excel ;
- document ;
- lien ;
- image ;
- etc.

Ils peuvent avoir une couleur d'accent propre à leur type, mais sans créer une explosion chromatique.

---

# 9. Connecteurs et flèches

C'est un élément essentiel du langage graphique.

### Préférer

- lignes fines ;
- courbes douces ;
- pointillés ou tirets ;
- petites pointes de flèche ;
- couleurs bleu clair ou turquoise ;
- faible contraste.

### Éviter

- grosses flèches ;
- flèches pleines très épaisses ;
- connecteurs noirs ;
- angles agressifs ;
- spaghetti de lignes.

Le connecteur doit **guider le regard**, pas devenir l'élément principal.

---

# 10. Flux animés

Lorsqu'un SVG animé est demandé, les animations doivent être **subtiles**.

## Animations recommandées

### Flux

Des pointillés peuvent se déplacer lentement :

```text
- - - - - - - >
      •
```

### Particules

Quelques petits points lumineux peuvent circuler le long des connecteurs.

### Noyau / cerveau

Le cerveau peut avoir une pulsation très faible :

- légère variation d'opacité ;
- très légère variation d'échelle ;
- halo discret.

### Boucle d'apprentissage

Un ou deux points lumineux peuvent parcourir la boucle.

### Règle d'or

> **L'animation doit donner de la vie au schéma sans attirer l'attention sur elle.**

Pas de clignotement rapide.

Pas d'animation permanente spectaculaire.

Pas de mouvements brusques.

---

# 11. SVG : règle technique

Lorsque l'utilisateur demande un SVG animé, **ne pas utiliser le générateur d'image**.

Le fichier doit être construit comme un **SVG natif codé**.

### Exigences

- fichier `.svg` ;
- éléments vectoriels ;
- objets séparés autant que possible ;
- textes sous forme de `<text>` ;
- formes sous forme de `<path>`, `<rect>`, `<circle>`, etc. ;
- animations CSS / SVG / SMIL intégrées ;
- aucun raster nécessaire sauf demande explicite.

### Deux modes possibles

#### SVG natif complet

Tout est reconstruit en vectoriel.

À privilégier lorsqu'on veut :

- modifier les éléments ;
- changer les couleurs ;
- déplacer les composants ;
- éditer le fichier dans Illustrator / Inkscape.

#### SVG animé fidèle à une référence raster

Si l'utilisateur veut conserver **au maximum l'apparence exacte d'un PNG validé**, conserver éventuellement le PNG comme image de fond intégrée et ajouter une couche SVG animée.

Cette solution est acceptable pour préserver une version validée à l'identique.

> [!important]
> Ne jamais prétendre qu'un SVG contenant un PNG est « entièrement vectoriel ».

---

# 12. Densité d'information

Le style doit favoriser la compréhension en présentation.

### Règle

**Un schéma = une idée principale.**

Il vaut mieux :

- 5 éléments très lisibles

que :

- 15 éléments petits et précis.

Les détails peuvent être montrés dans un second schéma ou une slide suivante.

---

# 13. Espace blanc

L'espace blanc est une composante essentielle du style.

Prévoir :

- des marges généreuses ;
- des zones respirantes entre les blocs ;
- des alignements nets ;
- des distances régulières.

Ne pas chercher à remplir tout l'espace disponible.

---

# 14. Principes de représentation

Pour les schémas stratégiques du projet, privilégier :

### 1. Une métaphore visuelle forte

Exemples :

- cerveau ;
- réseau ;
- flux ;
- écosystème ;
- architecture ;
- boucle ;
- couches.

### 2. Une structure logique immédiatement lisible

Le spectateur doit comprendre la logique principale en **3 à 5 secondes**.

### 3. Une progression visuelle

Utiliser les flux, la position et la hiérarchie pour raconter le concept.

### 4. Peu de texte

Le schéma accompagne la présentation orale.

Il ne doit pas devenir un document à lire.

---

# 15. Cohérence entre les schémas

Tous les nouveaux schémas doivent donner l'impression d'appartenir à la **même famille graphique**.

Conserver autant que possible :

- la même palette ;
- la même typographie ;
- les mêmes rayons de cartes ;
- les mêmes épaisseurs de traits ;
- le même style d'icônes ;
- le même style de connecteurs ;
- le même niveau d'ombre ;
- le même niveau de détail ;
- le même rapport entre texte et espace blanc.

Le contenu change.

**Le langage graphique ne change pas.**

---

# 16. Prompt maître à réutiliser

Copier-coller ce bloc au début d'une nouvelle demande de schéma :

> ## CHARTE GRAPHIQUE À RESPECTER
>
> Crée ce schéma comme un nouvel élément de la même famille graphique que **« Le Cerveau collectif »**.
>
> Respecte strictement les principes suivants :
>
> - style moderne, professionnel, stratégique et technologique mais humain ;
> - fond blanc / blanc très légèrement bleuté ;
> - palette dominée par bleu nuit + bleu principal, avec turquoise et violet uniquement comme accents ;
> - typographie sans-serif moderne, idéalement Inter ;
> - titres bleu nuit, hiérarchie typographique claire ;
> - cartes blanches légèrement arrondies avec bordures fines et ombres très discrètes ;
> - icônes vectorielles simples, cohérentes, plutôt outline/flat ;
> - avatars illustrés et diversifiés pour représenter les personnes ;
> - connecteurs fins, courbes, pointillés ou tirets, avec petites pointes de flèche ;
> - beaucoup d'espace blanc ;
> - très peu d'effets décoratifs ;
> - pas de 3D réaliste, pas de dark mode, pas de couleurs saturées multiples ;
> - lecture logique claire de gauche à droite lorsque le sujet s'y prête ;
> - maximum 4 à 6 grandes zones conceptuelles ;
> - privilégier une métaphore visuelle forte ;
> - le schéma doit être compréhensible en quelques secondes pendant une présentation ;
> - conserver exactement le même ADN visuel que le schéma de référence.
>
> **Ne réinvente pas la charte graphique. Adapte le contenu à cette charte.**
>
> Si je demande un SVG animé, construis un **SVG natif codé** et non une image générée. Les animations doivent être très discrètes : flux de particules, tirets animés, halos et pulsations légères.

---

# 17. Prompt pour un nouveau schéma à partir d'une image

Lorsque je fournis un schéma de référence :

> **Utilise cette image comme référence graphique, pas comme contenu à recopier.**
>
> Analyse d'abord sa composition, sa hiérarchie, sa palette, ses icônes, ses connecteurs, ses espacements et son niveau de détail.
>
> Recrée ensuite mon nouveau schéma avec **le même langage graphique**, tout en adaptant complètement la structure au nouveau concept.
>
> Le résultat doit sembler avoir été conçu par le même designer et appartenir à la même série de présentations.

---

# 18. Prompt spécifique pour une animation

> Transforme ce schéma en **SVG animé natif**.
>
> Conserve la composition et le design validés.
>
> Ajoute uniquement des animations légères :
>
> - déplacement lent de particules sur les flux ;
> - animation discrète des connecteurs ;
> - légère pulsation des éléments centraux ;
> - boucle d'apprentissage parcourue par un signal lumineux ;
> - éventuels halos très subtils.
>
> Les animations doivent rester élégantes et quasi imperceptibles au premier regard.
>
> **Ne génère pas de PNG ou de JPG.**
>
> Je veux un fichier `.svg` réellement exploitable dans un navigateur, avec les animations intégrées au fichier.

---

# 19. Checklist avant validation

Avant de valider un nouveau schéma, vérifier :

- [ ] Même ADN graphique que « Le Cerveau collectif »
- [ ] Fond clair
- [ ] Palette limitée
- [ ] Bleu dominant
- [ ] Turquoise réservé aux flux / apprentissage
- [ ] Typographie cohérente
- [ ] Icônes homogènes
- [ ] Connecteurs fins
- [ ] Pas de grosses flèches
- [ ] Cartes légères
- [ ] Ombres discrètes
- [ ] Beaucoup d'espace blanc
- [ ] Lecture immédiate
- [ ] Une idée principale
- [ ] Pas de surcharge
- [ ] Compatible avec une présentation stratégique
- [ ] Animation discrète si animation demandée

---

# 20. Philosophie générale

> **La technologie doit être visible, mais jamais décorative.**

Le design doit traduire :

**Connaissance → Connexion → Intelligence → Action → Apprentissage**

Le schéma doit donner une impression de :

**clarté · intelligence · maîtrise · confiance · souveraineté**

et non de :

**complexité · gadget technologique · futurisme · surcharge visuelle**.
